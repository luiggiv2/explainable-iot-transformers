- **Dataset(s)**: 10 open-sourced traffic datasets spanning 229 traffic types — confirmed verbatim from the arXiv abstract ("We evaluate TrafficLLM across 10 distinct scenarios and 229 types of traffic") and cross-checked against the official GitHub repo (github.com/ZGC-LLM-Safety/TrafficLLM), whose README "Traffic Datasets" table lists exactly 10 traffic datasets (spanning 14 downstream task categories: MTD, BND, MDD, WAD, AAD, EVD, TBD, EAC, WF, CD for detection; MTG, BTG, EVG, EAG for generation) totaling over 0.4M traffic samples; individual dataset names not enumerated in the fetched README table text — `[VERIFICAR]` if exact per-dataset names are needed.
- **Models / Methods**: Adapts general-purpose (large, decoder-style) LLMs to traffic analysis via a dual-stage fine-tuning framework: (1) traffic-domain tokenization to translate raw/structured traffic into instruction-following text, (2) dual-stage tuning pipeline combining generic traffic-representation learning with task-specific instruction tuning, and (3) EA-PEFT (extensible adaptation via parameter-efficient fine-tuning) to add new scenarios without full retraining.
- **Key metrics reported**: F1 range 0.9320–0.9960 across 229 traffic types; detection F1 = 0.9875 (up to 80.12% relative improvement over existing detection methods); generation F1 = 0.9483 (up to 33.92% improvement); +18.6% performance gain on unseen traffic scenarios.
- **XAI method (if any)**: None reported.
- **Relevance to our RQs**: Relevant to RQ1 as the most recent (2025) example of applying general-purpose LLMs (not small encoders) to traffic analysis with a strong emphasis on generalization across many traffic types via PEFT — a useful counterpoint to our "small encoder, single security-focused dataset, deep XAI" strategy. Highlights a research-gap direction (see final report) around LLM-scale traffic models lacking built-in explainability.
